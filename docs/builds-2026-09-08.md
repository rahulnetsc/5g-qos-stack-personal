## 1. M-5 — LCG = DRB ID: registration

**Registered 2026-09-08, before the diff.**

### 1.1 The deployed rule, from the C

Three facts, each from the full checkout (`Oai_Ran_QoS_Supported_MultiDRB`,
branch `twotier`), none from the vendored subset:

1. **One QoS flow per DRB.** `rrc_gNB_radio_bearers.c:498-505` sets every
   multiplexing limit to 1 — `MAX_QOS_FLOWS_PER_DRB_DC_GBR`, `_GBR`,
   `_NON_GBR` and `_TOTAL` are all `1` — so `nr_rrc_find_suitable_drb_for_qos`
   never reuses a DRB and `nr_rrc_assign_drb_to_qos_flow` creates one per
   flow.
2. **DRB ID = lowest free integer from 1.** `nr_rrc_add_drb`
   (`:248-263`) loops `for (drb_id = 1; ...)` and takes the first unused.
   So DRB IDs are the per-UE **setup ordinal**.
3. **LCG = DRB ID, capped at 7.** `nr_radio_config.c:3781-3785`:
   `long lcg_id = drbId; if (lcg_id > 7) lcg_id = 7;`. The comment
   `// LCG = DRB ID, LCID = DRB ID + 3` appears in **both** branches
   (`gNB_scheduler_ulsch.c:51-52`).

**Consequence: LCG is a per-UE bearer ordinal, not a function of 5QI.**
LCG 0 is never a DRB; it is the SRB group
(`get_SRB_RLC_BearerConfig(..., logicalChannelGroup=0)`). The one line of
calibration-log evidence agrees: `UE 1: created new DRB 1 for QFI 1 (5QI 9)`
→ LCG 1.

### 1.2 What this replaces

`scheduler/flow.py::FIVE_QI_LCG`, an **invented** 5QI→LCG table (its own
comment said so; README §8 carried it as `[OPEN: HARDWARE/DECISION]`). It
put 5QI 1 and 3 on **LCG 0** — the SRB group — which is the M-5 trap: wiring
`has_srb` to the C's own predicate (`per_lcg[0] > 0`) would have read every
telemetry-backlogged UE as having control traffic pending.

### 1.3 Two stated assumptions

- **Setup order = declaration order within the UE.** The C assigns DRB IDs in
  the order QoS flows arrive in the PDU-session setup; the simulator's only
  proxy is the scenario's flow-list order per UE. Every scenario builder
  lists a UE's flows together, so this is well-defined; it is stated because
  nothing in the repo can verify it.
- **A simulator flow is one QoS flow.** Flows here are unidirectional; a
  deployed QoS flow is one DRB carrying both directions. The port shares a
  DRB between a DL and a UL flow with the same `(ue_id, qfi)`; the census
  below finds **zero** such pairs in any built scenario, so the rule has no
  instance today.

### 1.4 Census of every built scenario under the rule (`scratchpad/lcg_census.py`)

19 scenario builds: `scenario(1..6)`, the three parametric mixes plus `bg`
and `shared_lcg`, four fleet compositions at N=8, G12, G11, and the three
G9 builds. Findings:

- **No UE exceeds 7 bearers**, so the cap at 7 never binds and no two data
  flows ever share an LCG under the deployed rule.
- **Zero `(ue, qfi)` pairs in both directions.**
- **Collision structure changes in exactly ONE scenario:**
  `parametric[factory, bg]` — today UE 8's 5QI-9 best-effort flow and the
  5QI-8 aggressor share **LCG 6** (the aggressor set `lcg=6` explicitly,
  which was the 5QI-9 default). Under the deployed rule they are DRB 4 and
  DRB 5, separate LCGs. **This is G6's and G7's cell.**
- `parametric[factory, shared_lcg]` is the H5 divergence axis: it forces
  two UL flows onto one LCG, which the deployed RRC **cannot produce**
  (`MAX_QOS_FLOWS_PER_DRB_TOTAL = 1`). Kept as an explicit override — moved
  from LCG 0 to **LCG 1**, off the SRB group — and labelled a divergence.

### 1.5 The port

- `scheduler/flow.py`: `FIVE_QI_LCG` / `lcg_for_5qi` / `DEFAULT_LCG`
  deleted. `assign_deployed_lcgs(flows)` assigns per-UE DRB ordinals to
  every flow left at `LCG_UNASSIGNED`; `LCG_SRB = 0`, `LCG_MAX_DRB = 7`.
  `FlowConfig.__post_init__` no longer resolves `-1` (it cannot — the
  ordinal depends on the UE's other flows).
- `sim/config.py::ScenarioConfig.__post_init__` is the ONE resolution
  point: it sees the complete flow list. Idempotent, so
  `dataclasses.replace` (G12's `permute_flows`) keeps the resolved LCGs —
  **the permutation control stays a declaration-order control and does not
  silently become an LCG-assignment control.** G11's rotation happens
  before its `ScenarioConfig`, so it resolves first, for the same reason.
- Every consumer that indexes by LCG (`BsrModel`, `Reservation`,
  `TwoTier`, `TrafficModel`) **refuses** an unassigned flow rather than
  indexing `[-1]`, which Python would silently accept as `[7]`.
- Explicit `lcg=6` on the three background aggressors (parametric, G12,
  G9) removed — derived.

### 2.2 Three premises in the brief, checked against the C

1. **"SRB sets `has_srb`, which BOTH QoS comparators read as their top
   tier."** — **Reservation only.** The reservation branch has the tier in
   both directions (`gNB_scheduler_ulsch.c:2005-2017, 2167-2176`;
   `_dlsch.c:687-699, 830-842`) plus a control-only sizing cap (`:2503-2508`,
   `:1015-1018`). **The two-tier branch has no `has_srb` at all**: its UL
   priority loop looks up `lcid = lcg + 3` and LCG 0 matches nothing
   (`gNB_scheduler_ulsch.c:41-70`, two-tier), so SRB backlog reaches only the
   scalar `B` (eligibility, sizing); its DL loop gates the QoS path on
   `lcid >= 4` (`_dlsch.c:26` of `update_dlsch_buffer`) so SRB bytes reach
   only `num_total_bytes`. **Ported as the branches are**: a top tier on
   Reservation, eligibility-plus-bytes on TwoTier.
2. **"Making it live changes ordering in every arm on every workload."** —
   **Only where SRB traffic exists.** The deployed RRC configures **no
   measurements** (no `measConfig` in any conf or log line, no
   `MeasurementReport` in the session), so after attach the SRBs carry
   **nothing** until a reconfiguration or re-establishment. On the guarantee
   workloads every UE is connected at slot 0 and never leaves, so **SRB
   traffic there is zero and the tier stays inert**; it wakes on G9's three
   builds and on any UE that hits sr-TransMax. This is the registered
   expectation; **the capture request is the arbiter** — a session capture
   showing periodic SRB traffic overturns it.
3. **"Expect this to invalidate more of the table than any other single
   change."** — Conditional on (2). If the deployment really has silent SRBs
   between events, the table moves on G9 and nowhere else; the always-on cost
   is the RO reservation, 12 PRB × 12 symbols in one slot per 20 ms
   (0.28 % of UL capacity), predicted **within seed noise** on every row.

### 2.8 Build 1.2 — SRB: the design, written before the code

**Flows.** `FlowConfig.is_srb` (new). Per UE, SRB1 and SRB2 as UL+DL flow
pairs on `lcg=LCG_SRB` (0), `qfi` −1/−2, priority **1 / 3**
(`get_SRB_RLC_BearerConfig(1, 1, ...)`, `nr_radio_config.c:3865`), non-GBR,
`traffic_kind="none"` (a new kind that generates nothing — traffic is
injected by the dialogue). `assign_deployed_lcgs` skips `is_srb` flows (they
are not DRBs and consume no ordinal); the census test allows LCG 0 for them
only. Added at the SCENARIO level by `with_srb(scenario)`, applied by the
campaigns when `--random-access` (srb on) — so every consumer of
`scenario.flows` sees them and `from_summary` stays consistent.

**Dialogues** (`sim/srb.py::SrbDialogue`): N-step request–response chains
through the ordinary buffer → scheduler → HARQ path; step i+1 is enqueued
when step i's bytes are fully delivered. The G9 app handshake becomes one
instance. Sizes: measured where the log gives them, CHOSEN otherwise, all
+8 B (PDCP 2 + MAC-I 4 + RLC-AM 2). Attach: RRCSetupComplete 41 (LCID-1
counter) → DLInfo 42 → ULInfo 24 → DLInfo 21 → ULInfo 60 → SMC 3 → SMComplete
10* → UECapEnq 8 → UECapInfo 300* → DLInfo 53 → ULInfo 13 → ULInfo 35 →
RRCReconfiguration 313 → Complete 10* (* chosen). Re-establishment:
ReestComplete 10* → RRCReconfiguration 313 → Complete 10*. Core-network
turnarounds: **0 ms, chosen, a lower bound** — the capture request asks for
stamps. Warm path and C-RNTI RA: no signalling.

**FSM.** With srb on, `RRC_ESTABLISH`/`REESTABLISH` end when the dialogue
ends (`ra_complete_this_slot` carries `is_full_setup=True`; no sampled
remainder). New gate `srb_active(state)`: SRB flows schedulable from
contention resolution until the DRBs come up; `JoinAwareBufferView` masks
non-SRB flows in that span; `ul_access`/`bsr` run for the UE (it has a
C-RNTI); the existing `radio_connected` edge (resets, RLF re-arm) stays at
`APP_HANDSHAKE` entry.
