## Part 2 — the classification question, answered before building

**Model C is a scenario treatment; the re-join seed is a MECHANISM CHANGE.**
Model C's trigger is a caller-supplied slot map; this one's is an internal
FSM edge. **So it needs a divergence justification, and "it fixes G9" is not
one.**

**The justification available is the one Model C already rests on:** real
hardware grants during attach and re-establishment (RACH msg3, then RRC
signalling on SRB), and those grants carry BSRs. This simulator has **no RA
procedure and no SRB traffic** (`has_srb` is hardcoded `False`), so a
re-attaching UE never receives a grant hardware would always give it. **The
seed supplies the effect of an input the deployed system has and the sim
lacks. It changes no scheduler, no ranking and no ported constant.**

### And the edge I first named was the wrong one

**Found by reading `sim/driver.py:316-335` before building.** Its own comment
says *"warm never reaches here at all (radio never drops)"* — **GT-6.1's
warm path is an app restart.** Seeding only at `radio_connected_this_slot`
**could not have affected the clause it was built for.**

The warm path reaches the same fault by a different door: app stops →
backlog drains → a BSR fires with no active LCG → `_assemble` memsets the
array and returns early on `fmt=="none"` → app restarts, backlog returns,
array still zero. **So the seed fires at BOTH `app_connected_this_slot` and
`radio_connected_this_slot`.**

### A second correction, caught by the observability counter

First implementation seeded **at** the edge and fired **0 times, refusing 7
as empty** — an app that has just restarted has produced no traffic yet.
**The `refused_empty` counter is what surfaced it**; a silent no-op would
have looked exactly like the treatment failing. Fixed to **arm at the edge
and fire at the first slot with backlog**, which is what Model C already
does at attach.

### M19 is 0.0 on every arm and every path — not a result

I registered: *"a p95 of exactly 0.0 is the failure signature, not a
result."* **It is 0.0 in all nine cells.** M19 is therefore **not scoreable**
here, and reporting it as "0 ms recovery, passing" would be exactly the
error the caveat was written to prevent. **M21 is 0.0 on the warm path too**
and carries the same caveat there.

**M18 is the one usable recovery statistic**, and it separates: TwoTier's
warm recovery p95 is **168.4 ms against PF's 16.5 — 10×**.

### TwoTier's RLF path registers its event and never completes it

**TwoTier: 1 of 1 reestablish events, M18 p95 = `None`.** That is §34.5a's
exact warning — *an arm can register its full scheduled count and complete
none of them* — and it is why the count assertion alone was never enough.
**Firing and finishing are different questions**, and TwoTier fires and does
not finish.

### The neighbour clause fails on TwoTier

**ΔM02 is 0.000 with CI [0.000, 0.000] on all nine cells** — saturated and
unable to move, exactly as registered. **Clause 4 rests on Δp98 alone.**

On Δp98, **TwoTier's neighbours are measurably WORSE when the joiner is
present: +3.08 ms [+2.22, +4.05] on warm and +2.35 [+0.37, +4.57] on rlf**,
both excluding zero. **And the sign is the surprising part:** the control
keeps the joiner UE but removes its join schedule, so in the control the
joiner is *always* transmitting. Neighbours should therefore be **better**
in the treatment, which is what PF shows (−0.62 to −1.77). **TwoTier's
neighbours are worse despite the joiner being absent part of the time.**

## What G9's verdict is

**Clause 1 (warm), 2 (cold), 3 (rlf): counts complete on every arm — G9 is
scoreable.** M18 gives PF ≈ Reservation ≪ TwoTier on every path, and
TwoTier never completes an RLF recovery. **Clause 4 (neighbours unaffected)
FAILS on TwoTier**, passes on PF and Reservation. **M19 and warm-path M21
are not usable statistics here and are reported as such rather than as
passes.**

**And the fifth instance is the statement worth making:** the same
intervention — supplying the BSR a real attach would have produced — clears
the lock-out in G5's completeness, G10's admissible fleet, the UL blackout
rate, and now G9's join counts. **One mechanism, four observations, one
intervention that clears all of them.** That is a stronger claim than four
rows, and it is what `docs/g5-mechanism-2026-09-05.md` should be read as
saying.
