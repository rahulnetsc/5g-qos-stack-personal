# G6 scored on the median — and the estimator choice turns out not to decide it

**2026-09-05.** Post-scaling records (n=40, regenerated on current code).
**The call: score clause 2 on the MEDIAN.** Rationale and sensitivity below.

## The call, and why

G6 reads *"every G1/G3/G5 statistic stays within its bound **and** shifts by
≤ +20 % relative"*. It fixes a number and **names no estimator over runs**.
Three readings are defensible — median, mean, per-run conjunction — and they
disagree.

**Chosen: the median**, because this workload demonstrably produces outlier
seeds. TwoTier's clause-2 mean on M02 is **+1087 %** against a median of
**+0.28 %**; on M06, mean **+42.6 %** against median **−0.41 %**. A mean over
40 seeds that a single run can move by three orders of magnitude is not
measuring the shift the clause is about.

**Both alternatives are reported alongside, so a different reading is
visible rather than hidden.**

## The result — clause 2 on the median

| metric | PF | Reservation | TwoTier |
|---|---|---|---|
| M01 | **+4.36 %** PASS *(mean +12.09 %, INCONCLUSIVE)* | −0.46 % PASS | **+4.52 %** PASS *(mean +60.36 %)* |
| M02 | *(no stated bound)* | −0.20 % PASS | **+0.28 %** PASS *(mean **+1087 %**)* |
| M03 | −0.30 % PASS | +0.10 % PASS | −0.42 % PASS *(mean +15.37 %)* |
| M05 | +0.00 % PASS | +0.00 % PASS | −28.55 % PASS |
| M06 | −1.19 % PASS | −0.45 % PASS | −0.41 % PASS *(mean +42.64 %)* |

**On the median, clause 2 PASSES on every metric and every arm.**

## AND THE ESTIMATOR CHOICE DOES NOT DECIDE G6

**This is the finding, and it was not obvious before scoring.** G6 is a
**conjunction**, and **clause 1 — "stays within its bound" — needs no
estimator at all**. It is a per-run bound check, and it fails:

| metric | PF | Reservation | TwoTier |
|---|---|---|---|
| M01 ≤ 100 ms | PASS 0/40 | PASS 0/40 | **FAIL 8/40** |
| M03 ≤ 500 ms | PASS 0/40 | PASS 0/40 | **FAIL 2/40** |
| **M05 ≥ 0.99** | **FAIL 3/40** | **FAIL 30/40** | **FAIL 34/40** |
| M06 ≤ 67 ms | PASS 0/40 | PASS 0/40 | **FAIL 14/40** |

**G6 FAILS on every arm, decided by clause 1, and the estimator ambiguity
never gets to matter.** The specification defect is real and stands — a
guarantee that names no estimator is under-specified regardless — but on
this data it is **not verdict-determining**.

### And the decomposition matters more than the verdict

- **PF and Reservation fail clause 1 on M05 ALONE.** M05's failures are now
  known to be an artefact of this simulator's missing attach procedure
  (`docs/attach-path-result-2026-09-05.md`) — under an attach path
  Reservation goes 7/10 → 1/10 marginal. **So PF's and Reservation's G6
  failure is inherited from an artefact and should be re-scored under the
  attach path before it is taken as real.**
- **TwoTier fails clause 1 on four statistics** — M01, M03, M05 and M06 —
  so only part of its failure is the M05 artefact. **TwoTier's G6 failure
  survives.**

## What goes to the test-plan owner

**A note, not a blocker.** The clause names no estimator over runs, and the
plan names a run-rule wherever it means one elsewhere (G10: *"all-pass in 5/5
runs"*). We chose the median and documented it. **The choice did not change
this verdict, but it would on data where clause 1 passes** — so the clause
should say which estimator it means before G6 is used as an acceptance gate.

## The control could not be run, and that is reported as unverified

`g6_seed_extension.py`'s own control — *"do stage 1's own 10 seeds
reproduce?"* — **could not run**: the stage-1 CSV is absent from the
post-scaling tree. The runner reports this as **unverified rather than as a
pass**, which is correct, and it is repeated here so the verdict is not read
as fully controlled.

## RE-SCORED UNDER THE ATTACH PATH — my prediction MISSES, and the surprise is TwoTier

**Prediction registered:** *"PF and Reservation fail clause 1 on M05 alone,
and M05's failures are the attach-path artefact — so if their clause 1 passes
there, G6's verdict differs by arm."*

**It does not pass. Clause 1, with the attach seed at slot 0 (n=40):**

| metric | PF | Reservation | TwoTier |
|---|---|---|---|
| M01 ≤ 100 ms | PASS 0/40 | PASS 0/40 | **FAIL 11/40** *(was 8/40)* |
| M03 ≤ 500 ms | PASS 0/40 | PASS 0/40 | **FAIL 15/40** *(was 2/40)* |
| M05 ≥ 0.99 | **FAIL 2/40** *(was 3)* | **FAIL 3/40** *(was 30)* | **FAIL 17/40** *(was 34)* |
| M06 ≤ 67 ms | PASS 0/40 | PASS 0/40 | **FAIL 40/40** *(was 14/40)* |

**Reservation's M05 collapses from 30/40 to 3/40** — the artefact was most of
it, as predicted. **But 3/40 is still a failure**, and PF's 2/40 likewise. **So
G6 still FAILS on every arm, and the specification defect stays moot.**

**MISS recorded: I predicted a verdict change and got none.** The M05
residual at 2–3 of 40 seeds is small but real, and a bound check does not
care how small.

### The unexpected result: the attach path makes TwoTier WORSE on latency

**M06 goes from 14/40 to 40/40 failing. M03 from 2/40 to 15/40. M01 from
8/40 to 11/40.** Only M05 improves (34 → 17).

**This is a real effect and it qualifies how the attach path has been
described elsewhere.** Relieving the starvation does not create capacity — it
puts the previously-locked-out UEs back into contention, and that contention
is paid for in latency by everyone. **The attach path is not uniformly
beneficial: it trades completeness for delay on the arm whose ranking is most
sensitive to load.**

**Consequence for the mechanism document:** the "one intervention clears four
observations" claim is about the *lock-out*, and it holds. **But "clears" must
not be read as "improves everything" — on G6's latency statistics the same
intervention makes TwoTier measurably worse**, and that belongs beside the
consolidation rather than only here.
