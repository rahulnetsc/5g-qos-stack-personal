What runs, each slot — and the boundary that is enforced through the whole thing

One slot loop, 0.25 ms per iteration. The scheduler under test is a library that imports nothing outside itself; everything it reads about the slot, the buffers and the channel arrives through structural Protocol views.

The per-slot loop, in execution order

1 · source gatean app-gated UE admits no traffic
2 · channelAR(1) SNR, blockage, fades
3 · RLF detectn310-armed t310 dwell
4 · join FSMattach / re-attach / recover
5 · HARQ dueresolve retries first — their PRB and CCE come out of this slot's budget before anything new is granted
6 · BSR triggersregular / periodic / retx
7 · scheduler.allocate()on a reduced slot, with masked buffers
8 · UE-side LCPthe UE fills its own TB
9 · deliver / expireledgers, metrics, handshakes

Where the boundary is, and why

Nothing in scheduler/ imports sim/ — verified, not asserted. sim/scorecard.py consumes only a RunRecord and never touches the driver or the config, so it can score records produced by anything, including an OAI adapter.

The boundary is not tidiness. A scheduler that can reach into simulator state gets information no real gNB has, and a scheduler that cannot be built is not a result. The standing question for every abstraction is which network element learns this, and how?

The worked example

On main, TwoTier._mac_lcp_fill chose the uplink intra-TB byte split using the gNB's own virtual queue. The gNB cannot see that split — it only ever sees aggregate per-LCG BSR; the UE decides, by its own logical-channel prioritisation.

That is why sim/ue_lcp.py lives in sim/. Putting it in the scheduler library would be the fidelity error it exists to correct.

What it is03 / 25

What is modelled — and, on the same slide, what is not

Modelled

  • MAC scheduling against a real grid. 55 PRB at 40 MHz, μ=2, DSUUU; PDCCH CCE budget 48 (D) / 32 (U) / 16 (S) at aggregation level 4.
  • The full uplink access chain. SR on PUCCH → sr-ProhibitTimer → grant → quantised per-LCG BSR → grant, with sr-TransMax exhaustion falling back to RACH.
  • BSR realism. Short/Long format selection and short-BSR aliasing, UE-side ceiling encode plus the gNB's +1 overestimation bump, the sched_ul_bytes crumb-collapse gate. Tables transcribed from nr_mac_common.c and checked byte-for-byte on every test run.
  • HARQ. Per-UE-per-direction process pools, k1/k2 timing, incremental-redundancy combining gain by attempt, a binary per-TB success draw, and a retry cap with real residual loss.
  • UE-side LCP — TS 38.321 §5.4.3.1, two rounds, the first PBR-bounded.
  • Channel. AR(1) SNR over TR 38.901 InF path loss and LOS probability, two-state Markov blockage, CQI reporting delay.
  • Link adaptation. A persistent per-UE-per-direction MCS index, computed at candidate-build time, matching the C's own timing.
  • Join / RLF with this deployment's own timers, read from the gNB startup banner.
  • Per-message and per-frame ledgers — PDU sets grouped by frame_id, so completeness and frame age are measurable, not inferred from throughput.

Not modelled

  • No PHY. No waveform, coding, channel estimation, or RACH contention resolution. BLER is a sigmoid, not a decoder.
  • No RLC segmentation or ARQ. sim/buffer.py is a byte-count FIFO. It does not know which bytes are in flight — which is exactly why a flow with a pending HARQ process is masked fully, not proportionally.
  • No PDCP or SDAP. QFI→LCG mapping goes through FIVE_QI_LCG, which that table's own comment flags as invented and non-standardised.
  • No TCP coupling. RTSP-pulled video's DL-control-into-UL-throughput back-pressure is deliberately unbuilt.
  • No MFBR enforcement anywhere in sim/. The field is accepted and silently ignored. This is what makes G7 structurally unanswerable.
  • Continuous TB sizing. No TBS lattice — grants are sized against demand, not quantised to a transport-block table.
  • No SPS / Configured Grant. The deployed scheduler defers it to a Phase 2 that was never built, so the model must not exceed it.
  • No mobility, no MU-MIMO, no CU/DU split.
  • OLLA is present in structure and inert: its offset is provably 0, because the round-1 telemetry its ratchet reads is structurally unobservable here.

Environment05 / 25

Channel: indoor-factory everywhere, and which parts are derived rather than chosen

The five InF sub-scenarios

InF-SL, InF-DL, InF-SH, InF-DH — sparse/dense clutter crossed with low/high BS height — and InF-HH, both antennas above clutter, whose LOS probability is unconditionally 1.0 so it never reaches an NLOS formula at all.

A correction worth stating. This project's own documents previously named four of these, omitting InF-DH, reconstructed from a session's recollection. Fixed by transcribing the tables from the actual spec text — Tables 7.4.1-1, 7.4.2-1, 7.2-4 and 7.8-7 — cited by table and page.

Derived vs. authored

Position-derived: a UE with a position gets its mean SNR — the large-scale term the AR(1) process reverts to — from InF path loss and a link budget, computed once per link at construction.

Scenario-authored: mean SNR and spread where no position is set (the base point is 20 dB uniform, coherence 2,000 slots), and scripted fades, which force SNR deterministically with no AR(1) noise so that “when exactly does it cross the sync floor” has an exact, repeatable answer.

Not a deployment value: the clutter parameters are the spec's own calibration-study example figures, not a measurement of any real factory.

Planned, not built

Mobility and a floor plan. Every UE position is static geometry. Correlated blockage across UEs is deferred with it.

One knob that is load-bearing

A transport block's MCS-pick SNR freezes at its original grant and is reused across every retry. So cqi_delay_slots decides whether a time-varying channel can interact with HARQ at all.

Measured: at delay 0 the blockage×HARQ effect was unreliable — 0–6,193 bytes lost across 7 seeds, overlapping the no-blockage baseline. At a realistic delay 8 it separated cleanly: 5,200–21,514 against 0–800. Every study in this branch runs at 8.

Execution06 / 25

Parallelism was accepted as a correctness property, not a speed-up

Sequential inside a run, parallel across runs

Slot i depends on slot i−1 through buffer occupancy, HARQ feedback arriving k1/k2 slots later, the per-UE throughput EWMAs and the virtual queues. That chain cannot be broken and is not.

What is independent is cells. Within a cell, seeds and arms stay ordered, paired_seeds is drawn up front from a fixed base seed, and every run is a pure function of (scenario, seed). Workers write nothing — the parent stays the single writer, so record ordering is the parent's, not a race.

The acceptance criterion was byte-identity

A smoke grid run at --workers 0 and --workers 4 produced bit-identical scored rows and an identical gate verdict. The online-metric computation was extracted into one function so the serial sink and the parallel worker share a code path — otherwise the determinism claim would rest on two implementations staying in step.

Why it had to be correctness. Every comparison in this study is within-seed: the same channel realisation replayed across arms. Paired seeds are the whole statistical basis. An unpaired look at one hypothesis produced a confident answer opposite to the paired one — so this is not a refinement, it is the difference between a right and a wrong result.

Why 10 workers and not 24

Memory binds first, measured. Peak RSS is 1.4–2.1 GiB per worker at the largest cells, about 20 GiB across 12 — on a 24-core, 30 GB machine.

A retention leak had already killed one stage: 25 GB RSS with 32 GiB of swap in use, thrashing rather than computing, at 756 of ~1,680 records.

And a design consideration, not measured here: each worker links its own BLAS, so 24 of them each spawning threads oversubscribes the machine.

Two operational traps, both paid for.

pkill -f does not reach multiprocessing spawn workers — their argv is the bootstrap. Killing the parent left 12 orphans holding 18.7 GiB that pgrep -f could not see. Kill children by PID.

And the leak was fixed with tests — then reintroduced one layer down inside the parallel worker, and the tests stayed green, because they pinned the helper and the parent, both of which were genuinely clean. What caught it was live memory instrumentation at 20 of 59 cells.

Speed, honestly: the claim is not that this is fast

407 configurations, 12,210 runs, 17.0 hours of simulated air time, in ≈5.9 hours of wall time. That is the number to lead with. What follows is why it must not be turned into a real-time-factor claim.

At every working fleet size this simulator is slower than the radio it models. The throughput comes from parallelism, not from the model being fast. End-to-end with 10 workers, measured over two real stages: 2.96× and 2.78× — call it ≈2.9×.

The testbed-equivalent comparison ranges from 8.6× to 37.2× depending on assumed per-cell reconfiguration time, and nobody has measured that. The defensible floor is the 2.9× pure-air-time number, which assumes nothing.

The two things with no ratio at all

1 · A testbed cannot replay a channel realisation.

Every comparison here is within-seed — the same fade, the same blockage, the same HARQ draws, across all three arms. A testbed must raise its sample count per cell to recover the same statistical power, so the time comparison above understates the gap. And on this project an unpaired comparison already produced a confident answer opposite the paired one.

2 · n_ues = 32 needs 32 robots.

The current testbed is two rfsim UEs. The admissible-fleet-size question — the headline procurement number — is not a matter of patience.

Lead with reachability, not with time. A speed claim invites the obvious and correct rebuttal: a testbed gives you real RF. “This study is not physically runnable” has no such rebuttal, and it is true.

Three qualifiers that travel with every number in this deck

1 · Any single-metric “who wins” claim is false by construction

PF meets zero GBR contracts and still wins the max-min floor: it spreads capacity so every flow gets something and none reaches 95 % of its GFBR; the QoS-aware arms concentrate it so some meet contract and others get nothing.

Quote both numbers together, every time either is quoted. And the ranking is not stable: it flips between workloads, and inside one grid it inverts as a function of fleet size. The lesson generalises; the ranking does not.

2 · A simulator defect invalidated every pre-fix published uplink figure

The Scheduling Request was gated on an empty→non-empty backlog transition, so a UL flow whose backlog never emptied could never raise another SR. Combined with the crumb-collapse gate, its reported buffer clamped to zero permanently.

A per-slot trace: one flow starved from slot 14 to the end of the run, backlog growing to 184,989 bytes and never granted again.

It produced a clean PF > Reservation > two-tier ordering that read as a scheduling property. Patched, the 8× spread collapsed to under 1 % and the ordering reversed. The regression check moved 5,689 field values across 15 of 20 records.

The schedulers were ported correctly. This was a simulator defect that made a correct port look like a scheduler property — the most dangerous shape a bug can take here.

3 · Some guarantees this tool structurally cannot answer

G7 needs the excess to be clipped at MFBR. No MFBR enforcement exists anywhere in sim/, so containment is observable and clipping is not. Hardware is the only test.

G2's real failure class is a BSR/SR desync. Truncated BSR is built, wired to the trigger 38.321 actually specifies, and unit-tested — and it still cannot fire, for a measured reason.

G9's second clause runs, and its input is not independent evidence: the attach delays are sampled between this deployment's own timer ceilings, so a p95 restates the configuration.

This project's credibility rests on having said so. A deck that omitted these would be weaker, not stronger.

What it means

Both QoS-aware schedulers abandon one camera feed outright. It produces roughly 148 frames in 5.0 seconds and delivers none of them inside the 150 ms deadline, while its seven siblings are fine. Proportional fair never does this — its worst feed stays above 98.6 % complete. Where the testing team should look

Score every camera feed on GT-3.1, not just the designated instrument asset — the failure is one feed of eight and it moves between robots. Run it at 8 robots or more at offered load ×1.0. Use completeness, never frame age.

What travels with the number

Modelled means replaced by something that reproduces the behaviour, not the implementation. Absent means it has no counterpart, and the mapping says so rather than pointing at a nearby-but-unrelated line range.

RRC / NAS / core — ABSTRACTED

Nothing ported. No RRC state machine, no reconfiguration signalling, no RACH contention resolution, nothing from openair3/.

What is used instead: the deployed gNB's own timer constants, read from its startup banner — t300 400 · t301 400 · t310 2000 · n310 10 · t311 3000 · n311 1 · t319 400 — driving a calibrated delay distribution (floor plus exponential excess) and an n310-armed t310 dwell detector.

Signed off, not assumed: full RACH contention is PHY-layer fidelity the simulator's non-goals exclude, and no G9 or GT-6 pass criterion needs it. They need realistic timing, not realistic contention resolution.

RLC · PDCP · SDAP — ABSENT

No counterpart to nr_rlc, nr_pdcp or openair2/SDAP. The buffer is a byte-count FIFO with no segmentation and no ARQ — which is precisely why a flow with a pending HARQ process must be masked fully rather than proportionally: the buffer drains by byte count, not by chunk identity, so a second grant would drain whichever bytes are oldest, not the ones in flight.

QFI→LCG mapping goes through a table whose own comment flags it as invented and non-standardised.

Error class 1 — the aggregate was computed over a different population than the claim

Five instances on this project. Each is the same shape: reading an aggregate as a statement about the population it is named for, rather than the population it is computed over. Three of them cost a published conclusion before they were caught.

G6 · cost a published conclusion

The worst-liveness-gap statistic takes a max over every flow and the PDB-violation rate byte-weights over every flow. So a 50 Mbps best-effort flood being correctly starved scored as fleet damage. It reported a Two-tier failure at +136.84 % and a 24-percentage-point violation-rate rise on all three arms.

The better an arm contained the flood, the worse it scored — the causal direction was inverted. All flows: +0.2313 / +0.2270 / +0.2055. Aggressor excluded: −0.0019 / −0.0022 / +0.0010.

Fixed by binding G6 to a new protected-fleet metric, not by editing the existing one — its all-flow domain is deliberate and other guarantees need it.

G6 again · the estimator, not the population

The same statistic's per-seed deltas were summarised by a mean of ratios, which read +136.84 % while the median read −0.22 % and 21 of 40 seeds improved. A ratio off a near-zero base has no bounded magnitude.

Median plus interquartile range is now the reporting default for every max-type statistic on this project.

G12 · inside the tool built to apply the rule

The clause-4 scorer's second version pooled across arms and reported “first degradation at nominal load” — true of Two-tier only. PF and Reservation stay clean until 102 % of the measured ceiling.

Caught by asking which rows entered the minimum before quoting it.

G5 · predicted before the data arrived, cost nothing

“33 of 40 seeds breach the video bar” sounds like thirty-three failures. It is 2 distinct flows. Two-tier's 35 are 4 flows, one accounting for 30.

A breach count is over SEEDS, never over FLOWS. Thirty failures and one chronically broken flow look identical in that number — and they call for completely different fixes.

This one was registered as a standing doubt before the data existed and confirmed on arrival. It is the cheapest instance in the list, and the only one that cost nothing.

G10 · caught while building this deck

The per-flow latency statistic names a worst flow, and that flow is the best-effort filler on 10 of the 12 fleet-size × arm cells at nominal load — on PF at 24 and 32 robots it is the camera instead.

So comparing arms on it compares different flows. It was pulled from the result table rather than shipped with a caveat.

The check, stated so it is mechanical

Before quoting any aggregate — a max, a mean, a rate, a count of breaches — name three things:

(a) the rows it is computed over  ·  (b) the rows the claim is about  ·  (c) whether they are the same set.

If they differ, the aggregate does not support the claim — no matter how large the effect or how tight the interval. Asking in advance is nearly free; three of the five instances above were caught only after publication.

Error class 2 — the mechanism returned nothing, and the metric reported success

Structurally different from class 1, and worth separating because the mitigation differs. In class 1 a computed value was wrong. Here every number was correct for the events that happened — there simply were none. No metric caveat can catch this, because a caveat qualifies a computed value. G9 · the clearest instance

The scripted deep fade was written half the length of t310. The dwell re-armed, radio link failure was never declared, zero join events occurred — and the recovery metrics reported instant recovery.

The diagnosis, kept verbatim because a later reader will hit it: depth arms the timer, duration expires it. Two identically named signal-floor fields exist on different objects, and the driver constructs the detector's one — so setting the other does nothing. t310 is 2,000 ms, which at this numerology is 8,000 slots, and the fade must outlast it.

G9 again · and “at all” is too weak

The campaign implemented the lesson above as a non-zero check, and it passed on every run — while Two-tier recorded 3.8 of 10 scripted warm restarts and 1.0 of 5 cold cycles.

“Did the mechanism fire at all” is a weaker question than “did it fire as often as the scenario specifies”, and the gap between them is exactly where a partially degenerate run hides.

A partially degenerate run is not a smaller sample of the same thing. The events that survive are self-selected — here, the ones whose predecessor finished before the next was scheduled — so the arm is measuring a different population. Derive the expected count from the schedule and assert equality.

G12 · the instrument goes blind where the failure is total

Clause 4 was first scored on the telemetry liveness gap alone and returned UNSCOREABLE. The gap is undefined on 116 ramp points — because the statistic excludes any flow with fewer than two completions, and a flow down to one delivered message per run has no gap to measure. It goes blind while still delivering, not only when silent.

Rescoring on the PDB-violation rate moved the verdict from UNSCOREABLE to MISS, i.e. against the registered expectation — the honest direction for a post-hoc correction to run.

G9 / the recovery metric · green by construction

The SLO-recovery metric tests head-of-line age, and the buffer evicts a queue head before it can age past its deadline. So age is capped by construction and a never-delivering flow reads green, always.

Measured: 0 of 30,000 slots exceed the deadline on a robot dropping 1,396,203 bytes. The metric has no red state for this class at all.

Uplink buffer reporting · what finally caught one

Truncated buffer-status formats were wired to the wrong trigger and 36 unit tests passed — every one of them constructing the precondition it was testing. A test that builds its own precondition cannot discover that the precondition never occurs.

What caught it was an at-scale run producing an arithmetically impossible count: 144,000 — exactly 6 robots × 3 logical-channel groups × 8,000 slots. Ask of any surprising count: does it factor into the run's own dimensions? A value equal to an exact product of the grid's shape is almost never a measurement.

The check

Run it at scale and ask whether the precondition occurs at all — then assert the expected count, derived from the schedule and never restated in prose.

Applied to a forward-looking note rather than to a landed mechanism, this is the cheapest place in the whole process to spend the effort: a counterfactual probe costs hours, and discovering the same thing after a mechanism ships costs a work package.
